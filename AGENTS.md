# AGENTS.md

## Project

Astro 7 + TypeScript website template.

Requires Node `>=22.23.4` (Astro 7) and the pinned `pnpm@10.18.0` (`packageManager`);
the Docker build uses `node:24-alpine`.

## Quick Commands

| Command             | Purpose                                                                         |
| ------------------- | ------------------------------------------------------------------------------- |
| `pnpm dev`          | Start dev server (localhost:4321)                                               |
| `pnpm build`        | Build for production                                                            |
| `pnpm preview`      | Preview production build                                                        |
| `pnpm seo`          | Regenerate `src/data/seo-manifest.json` with seoslug (needs Python + `seoslug`) |
| `pnpm og`           | Regenerate `public/og.jpg` (needs ImageMagick)                                  |
| `pnpm lint`         | Run ESLint                                                                      |

| `pnpm format:check` | Check formatting without writing                                                |

## Structure

```
src/
├── components/   # Astro (.astro) components
├── layouts/      # Astro layouts
├── lib/          # Utilities (cn, etc.)
├── pages/        # Route pages (.astro)
└── styles/       # Global CSS
```

## Conventions

- **Class merging**: Use `cn()` from `@/lib/utils` (tailwind-merge + clsx) never raw template literals for conditional classes.
- **Astro components**: `.astro` extension, use Astro fetch/frontmatter for data and server rendering.
- **Path alias**: `@/` maps to `src/` (configured in `tsconfig.json`).
- **SEO**: Add `<Layout title="..." description="...">` on every page. `Layout` renders `<Seo>` from the committed `src/data/seo-manifest.json`, generated by seoslug (`pnpm seo`). Run `pnpm seo` after adding or renaming a page.
- **Fonts**: Import Fontsource CSS in layout frontmatter (e.g. `@fontsource/inter/400.css`).
- **Images**: Use Astro's built-in `<Image />` from `astro:assets` for optimized images (no extra package needed).
- **Dark mode**: Tailwind `dark:` variants work out of the box, no class switching is configured by default.
- **Awesome feed**: `/projects` and `/orgs/` are **prerendered at build time** from the catalogue feed (`src/lib/catalogue-build.ts`, override with `AWESOME_FEED_URL_BUILD`), so the HTML carries the real entries and an `ItemList`. Each card ships its filter metadata in `data-filter`, and the client filters by toggling visibility — filtering keeps working even if the live refresh fails. If the build fetch fails the pages fall back to the old client-only shell with the "under maintenance" notice. Filtering helpers live in `src/lib/awesome.ts` (pure, covered by `pnpm test`).

## Framework Notes

- **Partytown** is configured with `forward: ['dataLayer.push']`, uncomment/add analytics forwarding in `astro.config.mjs`.
- **Sitemap** auto-generates at build from `src/pages/` routes, the `site` URL in `astro.config.mjs` must be updated before production.
- **seoslug** generates Open Graph, Twitter card, canonical, robots, and JSON-LD metadata per route into `src/data/seo-manifest.json`; `Layout` renders it via `src/components/Seo/Seo.astro`.
- **llms.txt / llms-full.txt** are generated into `dist/` by `scripts/generate-llms.mjs`, which runs as part of `pnpm build`.

## Toolchain Quirks

- `prettier-plugin-astro` is required for `.astro` formatting, it will not format `.astro` files without being listed in `.prettierrc` plugins.
- ESLint's `astro-eslint-parser` is configured only for `*.astro` files via the overrides block, `.ts` files use the `@typescript-eslint/parser` normally.
- `compressHTML: true` is intentional: Astro 7 defaults to `'jsx'` whitespace handling, which strips the space between inline elements. Keep `true` to preserve Astro 5/6 output.
- Astro 7 uses the Rust compiler, which rejects unclosed tags and no longer auto-corrects invalid nesting. Close every non-void element.
- Content collection config lives at `src/content.config.ts` (the old `src/content/config.ts` location was removed in Astro 6) and imports `z` from `astro/zod`.
- `build.cssMinify` is now Lightning CSS by default in the Vite 8 bundled with Astro 7, so the explicit `lightningcss` settings in `astro.config.mjs` are redundant but harmless.

## Agent infrastructure

Machine-readable discovery for AI agents is part of the site, not an add-on:

| Surface                | File                                                            | Notes                                                                                                                                                                                                         |
| ---------------------- | --------------------------------------------------------------- | ------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------- |
| Markdown negotiation   | `functions/_middleware.ts`                                      | `Accept: text/markdown` returns markdown plus `x-markdown-tokens`; HTML stays the default. The converter is DOM-free on purpose — Cloudflare's workerd has no DOM, and `turndown` crashed it with error 1101. |
| MCP server             | `functions/mcp.ts`                                              | Stateless Streamable HTTP at `/mcp`; tools `search_projects`, `list_categories`, `get_site_page`, `get_contribution_steps`.                                                                                   |
| Health                 | `functions/api/health.ts`                                       | Backs the `status` relation in the API catalog.                                                                                                                                                               |
| API catalog (RFC 9727) | `public/.well-known/api-catalog`                                | Extensionless, so `_headers` sets `application/linkset+json`.                                                                                                                                                 |
| OpenAPI                | `public/openapi.json`                                           | Describes `/api/feed`, `/api/health` and `/mcp`.                                                                                                                                                              |
| MCP server card        | `public/.well-known/mcp/server-card.json`                       | Must match the tools in `functions/mcp.ts` when they change.                                                                                                                                                  |
| ARD manifest           | `public/.well-known/ai-catalog.json`                            | Also advertised via `Agentmap:` in `robots.txt` and `<link rel="ai-catalog">` in `Layout`.                                                                                                                    |
| Skills index           | `public/.well-known/agent-skills/index.json`                    | **Generated** by `scripts/generate-agent-skills.mjs` during `pnpm build`; edit the `SKILL.md` files, never the index.                                                                                         |
| auth.md / PRM          | `public/auth.md`, `public/.well-known/oauth-protected-resource` | The site issues no tokens, so `authorization_servers` is empty by design. Do not invent an issuer.                                                                                                            |
| WebMCP                 | `src/components/AgentTools/AgentTools.astro`                    | Registers browser tools on load when `document.modelContext` exists; no-ops otherwise.                                                                                                                        |

`pnpm test` runs `scripts/test-agent-endpoints.mjs`, which drives all three
Functions directly (17 checks, including the www→apex redirect). Keep it green
when changing agent surfaces.

## SEO invariants

- Every page declares `<Layout title description>`; titles are 30-60 characters
  and descriptions 120-155. `pnpm seo` regenerates `src/data/seo-manifest.json`
  from those props (it also injects JSON-LD, canonical and breadcrumbs). Never
  hand-edit the manifest: it is generated and excluded from Prettier.
- `/projects/` and `/orgs/` must keep real content in the raw HTML — that is the
  whole point of the build-time fetch. If you touch `catalogue-render.ts`, check
  with `curl -s https://librecourse.uy/projects/ | grep -c github.com`.
- `www` must 301 to the apex (handled in `functions/_middleware.ts`).
- Sitemap `lastmod` comes from the manifest's git dates (see `astro.config.mjs`).
